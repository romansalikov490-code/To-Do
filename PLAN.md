# План реализации AI Task Manager

## 1. Фронтенд

1. Создать проект Next.js с App Router, TypeScript и Tailwind CSS. Сформировать адаптивную страницу в минималистичном стиле: шапка с прогрессом, блок умного ввода и матрица 2 × 2.
2. Добавить текстовое поле, кнопку «Разобрать с ИИ» и голосовой ввод через Web Speech API (`ru-RU`). Предусмотреть сообщения об ошибках и неподдерживаемом браузере.
3. Реализовать четыре квадранта: «Срочно и важно», «Важно, не срочно», «Срочно, не важно», «Не срочно и не важно». Показывать в них карточки с чекбоксом, категорией, дедлайном, причиной приоритета и удалением.
4. Добавить перенос карточек между квадрантами и доступный альтернативный способ выбора квадранта с клавиатуры. Отображать состояния загрузки, ошибки и пустые состояния.
5. Добавить кнопку «Разбить на шаги» и мини-чеклист с оценкой времени. Прогресс в шапке рассчитывать по выполненным основным задачам.

## 2. База данных

1. Подключить Turso через libSQL; хранить URL и токен только в переменных окружения сервера.
2. Создать таблицы `tasks` и `subtasks` со связью по идентификатору задачи. Для задач хранить название, категорию, квадрант, причину, необязательный дедлайн и статус; для шагов — название, минуты и статус.
3. Реализовать Route Handlers для получения, изменения и удаления задач, а также для изменения статуса подзадач. Удалять шаги вместе с родительской задачей; операции создания нескольких записей выполнять транзакционно.
4. Проверить сохранение после перезагрузки, перенос между квадрантами, статусы и удаление.

## 3. Gemini API

1. Добавить `GEMINI_API_KEY` в серверное окружение; не передавать его в клиентский код. Вызовы Gemini выполнять только из Route Handlers.
2. Настроить `gemini-3.5-flash` и Structured Output с JSON-схемой для извлечения списка задач, категории, квадранта, дедлайна и обоснования до семи слов. Передавать текущую дату для интерпретации относительных сроков; не выдумывать отсутствующий дедлайн.
3. Создать отдельный маршрут декомпозиции с JSON-схемой для 3–5 конкретных шагов и оценки времени в минутах. Проверять структуру и ограничения ответа на сервере перед записью в Turso.
4. Обработать недоступность API, некорректный ответ и повторные запросы; проверить полный сценарий с настроенными ключами.

## Настройка и ограничения

Документировать переменные `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` и `GEMINI_API_KEY`, запуск и проверку приложения. Без авторизации все посетители одной установки имеют доступ к общим задачам; развертывание следует выполнять в доверенной среде.
